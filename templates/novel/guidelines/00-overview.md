# 00. 全体像と三大原則

本ガイドラインは、生成支援の有無にかかわらず、読者の没入を妨げる機械的な反復、説明の空転、正書法事故、長編の整合性破綻を防ぐための執筆規約。

## 設計思想

生成支援を使った小説の欠陥は、表面的な言い換えだけでは消えない。**抽象動詞・テンプレ展開・派閥揺れ・記号事故**が重なるのを抑えるには：

1. **生成前**にキャラ・世界観・プロットビートを構造化して固定
2. **生成中**に正書法・禁則を制約条件として与える
3. **生成後**に確定的な書式事故を機械検査し、語彙・リズム・読後感は文脈と作品意図で判断する

禁止語や回数ノルマで人間らしさを演出しない。具体性、人物固有の判断、因果、含意、文脈に応じたリズムを設計し、検査結果は改稿候補として使う。

---

## 三大原則の詳説

### 原則1：記号は日本語正書法に従う

**Why**：マークダウン記法・半角スペース・派閥揺れの三点リーダ／ダッシュは、Web小説サイトで装飾されず文字列として浮く。これは生成AIの出力を未調整で貼り付けた痕跡として目立つ。

**How**：
- マークダウン強調 `**` `*`、見出し `#`、水平線 `---`、コードブロック ` ``` `、箇条書き `* - 1.` を**本文に出さない**
- 三点リーダは `……`（U+2026 を2つ＝偶数個）に統一。`・・・` `…` `...` 禁止
- ダッシュは `――`（U+2015 を2つ＝偶数個）に統一。`ーー` `──` `--` 禁止
- スペースは全角。半角スペースは英数字後の慣例位置以外で使わない
- ダブルクォート `" "` 禁止、強調は『 』
- 詳細は `01-writing-rules.md` 参照

### 原則2：抽象を避け、具体・五感・身体性で書く

**Why**：具体的な五感・固有名詞・物量感が不足し、抽象動詞「整える・削る・回す」、説明動詞「思った・感じた・〜ようだった」、雰囲気フレーズ「場を整えた・輪郭を持った」が重なると、「読後感が空虚」「商品パッケージ的」と感じられやすい。

**How**：
- 抽象動詞 → 具体動詞（「整えた」→「伝票を月別に並べ替え、誤記入を朱筆で消した」）
- 説明動詞 → 描写（「悲しいと思った」→「喉の奥が熱くなった」）
- 食事・服装・建物は、場面の選択や階級、生活、感情に効く具体物を選ぶ。五感を項目埋めで足さない
- 文末や文長の反復は、場面の速度と声を平坦にしている場合だけ崩す。現在形や体言止めを数合わせで混ぜない
- 詳細は `02-narrative-craft.md` 参照

### 原則3：設定は事前固定・全話一貫

**Why**：長編では設定参照が漏れると、髪色・性別・年齢・時系列・口調・敬称が章を跨いで（時には同一場面内で）ブレる。これが「致命的整合性破綻」観点として最も読者の興を削ぐ。

**How**：
- 新作開始前に `templates/` のシート群（character-sheet・world-bible・pov-plan・beat-sheet・plot）を埋めて**執筆前にフリーズ**する
- 視点（誰の目で書くか・誰が何を知っているか）は `work/pov-plan.md` で場面単位に割り当てる（三人称多元の中枢）
- 1話ごとの設計は `work/scene-cards/ep<N>.md` に落とす（視点キャラ・GMC・引き・previous_facts 抜粋）
- Claude Codeは `CLAUDE.md` の読み込み戦略に従い、現在状態→シーンカード→視点表→登場人物→現在アーク→必要な正典の順で参照する
- 詳細は `03-character-and-world.md` `04-structure-and-plot.md` 参照

## ファイル間の参照関係

```
CLAUDE.md（最優先。完了条件・読み込み戦略・状態管理・執筆規則）
  ├─ 00-overview.md（本ファイル：三原則）
  ├─ 01-writing-rules.md（記号・正書法）……原則1の実装
  ├─ 02-narrative-craft.md（視点・描写・台詞）……原則2の実装
  ├─ 03-character-and-world.md（設定）……原則3の実装（キャラ・世界）
  ├─ 04-structure-and-plot.md（構成・6層設計）……原則3の実装（時系列・章）
  ├─ 05-ai-guardrails.md（機械事故と定型化候補の分離）
  └─ 06-revision-checklist.md（章完成時の校正）

templates/（作品ごとにコピーして work/ 等に配置）
  ├─ character-sheet.md（キャラ固定設定。POVキャラは§視点フィルタ必須）
  ├─ pov-plan.md（視点運用表：視点割当・情報格差マトリクス。多元視点の中枢）
  ├─ world-bible.md（世界観Bible雛形。作品の正典は world-bible/ に作る）
  ├─ beat-sheet.md（採用した構造の転換点。Save the Cat版は任意）
  ├─ plot.md（中粒度プロット。作品基本情報＝字数・場面転換記号等の正本）
  └─ scene-card.md（1話単位の執筆設計）

.claude/skills/
  ├─ long-novel-orchestrator（新規執筆の入口）
  ├─ write-episode（1話執筆フロー）／validate-episode（3段バリデーション単体）
  ├─ narrative-style-web-novel（単一文体レイヤー。write-episode の中で使う）
  ├─ ai-novel-detector（文章・文体の事後診断・改稿優先度・引継ぎ票。外部評価のみ28観点）
  └─ humanize-ai-writing（診断結果を受けた本文改稿）
```

執筆フロー（1話単位の既定手順は write-episode スキルが管理する）：
1. 新作：`world-bible/`・`pov-plan`・`plot`・`character-sheet` を埋めて執筆前にフリーズ
2. 話の設計：`pov-plan` の視点割当を確認し、`scene-cards/ep<N>.md` を作る
3. 本文生成：`narrative-style-web-novel` の地の文主体／会話主体／混合モードで執筆。`01` `02` の規則を制約条件とする
4. 必須3段バリデーション：`scripts/check.sh` [NG]ゼロ → 視点・キャラ照合検査 → `ai-novel-detector` 文体診断 → 必要箇所を `humanize-ai-writing` で改稿 → 再検査（通すまで「完成」としない）
5. 台帳更新：canon-log・08-timeline §3・pov-plan §3 に確定事項を追記（証跡として引用報告）
