# AI文体診断（クラスタ走査＋文体観点）

文章・文体の機械的・定型的な特徴を、著者性ではなく観察事実として診断する。
完成条件は、根拠付きの所見、誤検出注意、改稿優先度、必要時の引継ぎ票が揃うこと。

## 役割境界

本Skillは**文章・文体専任**である。

| 対象 | 担当 |
|---|---|
| クリシェクラスタ・圧縮癖・装飾比喩・反復・均一化・読後感の走査と優先度評価 | 本Skill |
| 機械ルール（記号・正書法・空行・字下げ・マークダウン・文字種） | `check.sh`・`normalize_blanklines.py` 等の決定論スクリプト。本Skillは結果を証拠として引用するだけで、観点として再定義しない |
| 正典・視点・時系列・情報格差・人物像の照合 | `validate-episode`（毎話）／`long-novel-orchestrator` のアーク境界監査 |
| 展開のテンプレ化・あらすじ・キャラ構造など設計品質 | `guidelines/04-structure-and-plot.md`＋`novel-plot-advisor`（設計時）、アーク境界監査（事後） |
| 本文の改稿・接地・自然化 | `humanize-ai-writing` |
| 新しい話の執筆 | `long-novel-orchestrator` → `write-episode` |

例外は外部評価モードだけで、リポジトリ外作品には validate-episode が使えないため、整合・構造・メタ観点も [references/external-review.md](references/external-review.md) の範囲で扱う。

本Skillでは完成稿を書かない。局所的な修正方針は示してよいが、全文リライトは `humanize-ai-writing` へ渡す。

## 非断定原則

- 「AIが書いた確率」「確定」「ギルティ」「人間には不可能」と表現しない。観察結果は「機械的特徴が弱い／一部ある／目立つ」と改稿優先度で表現する。
- 単語・誤字・投稿頻度・ルビ・感想返信・他言語文字の一項目から生成手段を推定しない。タイプミスは中立の校正対象。
- 投稿者・作品名を名指しで糾弾せず、告発・通報・晒しを推奨しない。タイプミスを証拠として残す提案をしない。
- 規約・応募規定は、確認済みの規約文と提供情報がある場合だけ扱う。

## 正本の優先

novel-Standard配下では `AGENTS.md` → `guidelines/01〜06` → 作品正典を本Skillのヒューリスティクスより優先する。`check.sh`・`repeat_check.py`・`vocab_check.py`・`cliche_check.py` の検出規則を本Skill内で再定義せず、スクリプト結果を証拠として引用し、本Skillは文脈・累積・誤検出・読後感を評価する。**採否判断の正本は `guidelines/05-ai-guardrails.md §3-4` の場面テストと機能変化テスト**、圧縮癖・装飾比喩の分類は **§3-5 の5系統**とする。

リポジトリ外の作品には novel-Standard 固有の正書法・禁止語・空行規則を強制せず、投稿先・ジャンル・作品内の一貫性を基準にする。

## モード

ユーザー指定を優先する。

1. **通常診断**（既定。毎話の検証・単発の「AIっぽい？」）：[references/quick-signals.md](references/quick-signals.md) の走査と、`scripts/cliche_check.py` の結果を文脈判定する。
2. **Full Detect**（アーク境界・総合診断・重大な疑い）：[references/detection-checklist.md](references/detection-checklist.md) の文体観点と圧縮癖5系統を全話・全場面で照合する。話またぎのモチーフ計数を含む。
3. **外部評価**（リポジトリ外作品・合本の総合評価）：[references/external-review.md](references/external-review.md) で0〜100の改稿優先度スコアと28観点（整合・構造・投稿メタを含む）を扱う。
4. **Handoff**：改稿依頼があるとき、[references/handoff-contract.md](references/handoff-contract.md) の形式で `humanize-ai-writing` へ渡す。

## 実行手順

### 1. 対象と証拠範囲を固定する

本文・あらすじ・複数話・メタ情報のどれが提供されたかを分け、提供されていない情報は「判定不能」とする。外部作品のURLや作者名を追加要求しない。

### 2. 機械検査を先に使う

novel-Standardの原稿では `check.sh`・`cliche_check.py` を実行して結果を引用する。機械的に確定できる違反（記号・空行・文字種・マークダウン）はスクリプトの管轄であり、本Skillの所見はその先の文脈判断に限る。

### 3. クラスタ走査の文脈判定（通常診断の中核）

`cliche_check.py` の警告に対し、機械が拾えない4点を目視で判定する。

- **場面テスト**：その表現が更新するのは場面（視点人物の知覚・判断・行動・関係・利害）か、文飾か。文飾なら優先度を上げる（05 §3-4）。
- **人物間共有**：同じクラスタが複数人物の視点・台詞に現れていないか（1人の癖なら許容候補、全員なら均一化）。
- **説明の二重化**：台詞・動作で示した感情を、直後の地の文が感情名・理由・一般論で再説明していないか。
- **複合発火**：B1＋E1（胸の奥＋何か）、所作＋ヘッジ（わずかに目を細めた）、一拍＋静か＋決意、否定対句＋場面締め、圧縮癖＋比喩の重なりは単独警告より優先度を上げる。

### 4. 圧縮癖・装飾比喩を5系統で走査する

警告ゼロの箇所にも、`guidelines/05 §3-5` の5系統（役割の顔・声貼り付け／身体部位の判断主体化／心理の物品管理化／無生物の行為主体化／固有モチーフの密度超過）の走査をかける。変種の発見を目視に頼らず、`scripts/metaphor_sweep.py`（再現率優先の第1走査。正本 `guidelines/05 §2`）を実行して候補を場面テストで裁定する。**同じ構造の変種**（新しい役割名詞、新しい擬人化対象）が繰り返し出るなら `cliche_check.py` へのクラスタ追加候補として所見に含める。

### 5. 反復モチーフを作品全体で計数する（Full Detect時）

固有比喩・決め台詞・象徴物の再登場を話またぎで数え、機能変化テスト（05 §3-4）にかける。前回から意味・関係・状況が変わらない再登場を、初出と機能転換の回を残して削減候補にする。個別文の良否ではなく使用回数の分布を根拠にする。

### 6. 所見を証拠型で分類し、優先度を付ける

**規約違反**（スクリプト検出の引用）／**本文パターン**（反復・均一性・抽象化・圧縮癖）／**読後感**（根拠箇所併記）／**校正所見**（著者性へ結びつけない）。正典矛盾・視点違反に気づいた場合は所見に含めず、`validate-episode` の照合対象として報告する。

一項目の有無ではなく頻度・近接共起・広がり・作品意図を確認し、同じ原因からの派生指摘は二重加点しない。優先度は次の順に高くする。

1. 本文外ノイズ・文字種事故（スクリプト検出の引用）
2. 読解を妨げる反復、口調ぶれ、場面テストで落ちる文飾の密集
3. 作品固有の声を薄める抽象化、クラスタ飽和、モチーフの機能なき反復、均一性
4. 好みやジャンル慣行に依存する弱い所見

### 7. 改稿へ引き継ぐ

全文改稿が必要なら `handoff-contract.md` の形式でまとめ、各所見に削除→直叙→接地の序列（05 §3-4）に沿った改稿目標を付ける。

## 出力

1. **総括**：機械的特徴の強さと診断範囲を一文で。
2. **主要所見**：最大10件を重要度順に。列は「観点またはクラスタID／証拠型／該当箇所／読者への影響／誤検出注意／優先度」。
3. **系統別結果**（Full Detect時）：文体観点と5系統の該当・非該当・判定不能。
4. **限界**：短さ、資料不足、媒体差、正典不足。
5. **引継ぎ票**：改稿依頼がある場合だけ。

## 完了条件

- 診断範囲と判定不能項目が明確で、各指摘に根拠がある。
- 証拠型（規約違反・パターン・読後感・校正）を混同せず、正典・構造の照合を本Skillの所見として出していない（外部評価モードを除く）。
- スコアをAI生成確率として扱わず、全文改稿を本Skillで実行していない。
- **見落とし確認**（Full Detect時）：`metaphor_sweep.py` を実行し、残余候補が全件裁定済み（所見化または登録簿記載）である。
- **過剰検出確認**：所見の一部（目安1割）を再読し、慣用・実物・台詞・設定内表現を高判定にしていないことを確かめた。
