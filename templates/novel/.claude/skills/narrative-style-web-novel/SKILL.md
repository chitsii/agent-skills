# 日本語Web小説 文体レイヤー

## 役割

設計済みの場面を、小説本文として読める語り・会話・段落へ変換する。ジャンルや感情曲線を決めるSkillではなく、指定された内容をどう見せるかだけを扱う。

優先順位は次のとおり。

1. `CLAUDE.md`
2. `guidelines/01-writing-rules.md`、`guidelines/02-narrative-craft.md`、`guidelines/05-ai-guardrails.md §3-4・§3-5`
3. `work/pov-plan.md`、character-sheet、`work/style-samples.md`、scene-card、正典
4. 本Skill

上位資料と衝突する技法は使わない。具体的には、場面内は視点人物ひとりの知覚に留め、地の文の固有名は全員を呼び捨てにし、口癖と語尾は character-sheet にあるものだけを使い、段落と空行の長さは場面の速度に応じて変える。

作品に `work/style-samples.md` がある場合、規約より優先するのではなく、規約の範囲内で**そのサンプルの声に合わせる**。規則を満たしていても声が違えば直す。

## 所有しない作業

- 新規話の資料読込、保存、3段バリデーション、台帳更新、完了判定は `write-episode` が所有する。
- 既存本文の検査と改稿ループは `validate-episode` が所有する。
- AI的特徴の診断は `ai-novel-detector`、診断票に基づく改稿は `humanize-ai-writing` が所有する。
- プロット、章末の引き、曇らせ、救済、恋愛進行などは plot／scene-card の設計を受け取るだけで、本Skillから追加・変更しない。

単独で呼ばれた場合も、本文案または文体改稿だけを返し、ワークフロー全体を実行したと主張しない。

## 入力の確定

執筆前に、視点人物、場面目標、開始状態、終了状態、登場人物、既知情報、禁止事項を親ワークフローから受け取る。文体モードは次の順で決める。

1. 今回の依頼または場面単位の明示指定
2. scene-card の「文体モード」
3. plot の「既定文体モード」または `work/style-samples.md` §1 の基調
4. 指定がなければ「地の文主体」

同じ話の中でも場面の機能に応じて混合へ寄せてよい。ただし、指定された作品の基調を無断で反転させない。

## 3つの文体モード

### 地の文主体

- 視点人物の知覚、判断、動作、結果を軸に意味段落を作る。
- 会話は関係変化や選択を進める位置に置き、説明の代読にしない。
- 世界設定は、人物が使う、誤解する、代償を払う場面へ織り込む。
- 段落長と文長は場面の速度に合わせて変え、固定数をノルマにしない。

詳細は [references/prose-and-pov.md](references/prose-and-pov.md)。戦闘や設定開示がある場合は [references/action-and-exposition.md](references/action-and-exposition.md) も読む。

### 会話主体

- 会話で対立、情報差、関係変化を進め、短い地の文で位置、動作、反応、結果を接地する。
- 話者はcharacter-sheetの声、呼称、応答連鎖、必要最小限の動作または透明な発話タグで判別させる。
- 事実は読者に明瞭にし、感情や意図には含意を残す。情報不足をハイコンテクストと呼ばない。
- 同一場面の連続会話は原則として詰め、沈黙、転調、決定の余韻だけを意味のある空行で示す。

詳細は [references/dialogue-and-subtext.md](references/dialogue-and-subtext.md)。

### 混合

- 会話で衝突と反応を進め、地の文で空間、身体、判断、代償を受け持つ。
- 会話と地の文を比率で交互配置せず、ビートの機能に合わせて切り替える。
- 会話だけでは位置関係が失われる箇所、地の文だけでは対人圧力が鈍る箇所を補い合う。

迷う場合は混合にせず地の文主体から始め、対人衝突が始まった箇所だけ会話密度を上げる。

## 全モード共通の原則

1. 視点運用（三人称多元の定義、場面境界だけの切替、切替後3文のアンカー、他人の内面の推察形）と地の文の中立呼称は `guidelines/02-narrative-craft.md §1` を正本とする。
2. 視点人物が見聞きした具体物、五感、身体反応、人物固有の判断を優先する。
3. 台詞と地の文の声はcharacter-sheetに従う。固有の語尾や決め台詞をSkill都合で増やさない。
4. 人物を主語にする。身体部位・声・無生物を人の行為の主語にせず、役割・心理・時間帯を名詞で部位に貼り付けない（「目が言った」「仕事の顔で」「卓が笑った」型の禁止）。比喩・換喩・擬人化は、削って同じ情報が伝わるなら使わず、場面の核となる像だけを視点人物の経験へ着地させて一場面一つ以下で使う。許容条件と例外（定着した慣用・キャラシートに根拠のある身体機能・作中の実物）は `guidelines/05-ai-guardrails.md §3-4・§3-5` を正本とする。
5. 説明は必要な時に必要な量だけ出し、その場の選択または結果へ接続する。
6. 空行、括弧、三点リーダ、ダッシュ、ルビ、場面転換記号は `guidelines/01-writing-rules.md` を正本とする。
7. 固定の台詞比率、比喩数、文数、文字数、笑いの挿入回数を品質基準にしない。
8. 台詞と反復の規範——指示台詞の音読テスト（§4-8）、警句の密度と場面締め（§4-9・§2-6）、話またぎの逐語反復（§5-3）、職能比喩の配分と飽和注意語（§2-7、character-sheet §視点フィルタ、`work/vocab-watchlist.tsv`）——は `guidelines/02-narrative-craft.md` を正本とし、生成時から守る。

## 場面の書き方

1. 開始時の位置、圧力、視点人物の当面の欲求を短く接地する。
2. 各ビートで「知覚または発話 → 人物固有の判断 → 選択または反応 → 状態変化」を必要な分だけつなぐ。
3. 説明が必要なら、現在の行動を止めずに理解できる最小単位へ分ける。
4. 場面末ではscene-cardに指定された状態差分と引きへ着地する。Skill独自の引きを追加しない。

## 文体固有の自己点検

親ワークフローの検証前に、次だけを確認する。

- 視点人物の知覚と語彙を通して地の文が書かれているか。
- 地の文中の固有名は、視点人物を含む全員が敬称・役職名なしの中立呼称になっているか。台詞、引用、明示的な内心との適用範囲を混同していないか。
- 誰の台詞か、再読せず追えるか。判別のために不自然な役割語を足していないか。
- 会話場面にも位置、動作、身体反応、結果のいずれかが残っているか。
- 段落と空行に意味上の緩急があり、均一なパターンになっていないか。
- 地の文の主語を点検したか。「目が言った」「〜の顔で」「卓が笑った」型が残っていないか。比喩は一場面一つ以下で、削ると情報が減るものだけか。
- 切迫場面の指示台詞を音読して、仕様の読み上げに聞こえないか。台詞の警句と場面締めの警句が過密になっていないか。
- 直近話の言い回しを逐語のまま再利用していないか。
- 職能比喩（計測・観測・査定など）が感情の決め所へ流入していないか。飽和注意語が上限の見込み内か。
- 設定説明が現在の選択、誤解、代償のいずれかに関係しているか。
- plot／scene-cardにない感情曲線、救済、伏線、正典を追加していないか。

モード別の対照例、場面速度による文の形の変え方、崩れやすい4パターンの直し方は [references/style-examples.md](references/style-examples.md) にある。書き出しに迷ったとき、または自己点検で引っかかったときに読む。

## 引き継ぎ

- 新規エピソード全体：`long-novel-orchestrator` → `write-episode` → 本Skill
- 既存エピソードの検査・改稿：`validate-episode` 内で必要箇所に本Skill
- プロットや暗い展開の設計：`novel-plot-advisor` または作品の plot／scene-card
- 世界観の設計：`novel-worldbuilding-advisor`
