# validate-episode：既存本文の3段バリデーション

引数（`$ARGUMENTS`）はファイルパスまたは話数。話数だけなら `work/drafts/` から該当ファイルを特定する。複数ファイルも処理できるが、結果はファイルごとに分ける。

## 実行モード

### 検査モード（既定・読取専用）

「検査して」「診断して」「チェックして」「問題を報告して」など、評価だけを求める依頼で使う。本文や資料を変更せず、違反箇所、根拠、修正方針だけを報告する。`ai-novel-detector` の診断は行うが、`humanize-ai-writing` による改稿は行わない。

### 修正モード

「修正して」「改稿して」「違反ゼロまで通して」など変更を明示した依頼、または `write-episode` からの呼出しで使う。最小限の修正、humanize-ai-writing改稿、全段階の再検証まで行う。

依頼が検査だけか修正込みか曖昧なら、検査モードを選ぶ。

## 1. 機械検出

```bash
./scripts/check.sh --strict <対象ファイル>
python3 scripts/normalize_blanklines.py --check <対象ファイル>
python3 scripts/repeat_check.py <対象ファイル>
python3 scripts/vocab_check.py <対象ファイル>
python3 scripts/cliche_check.py <対象ファイル>
python3 scripts/state_check.py --strict
```

`repeat_check.py` は対象話と既存全話の12字以上の逐語一致を警告する。警告は[NG]と違い採否判断の対象で、変奏するか、意図的な定型として `work/continuity/phrase-allowlist.txt` へ理由つきで登録して解消する（`guidelines/02-narrative-craft.md §5-3` が正本）。検査モードでは警告と登録候補を報告だけし、allowlistを変更しない。

`vocab_check.py` は飽和注意語（`work/vocab-watchlist.tsv`）の話単位の出現数を上限と突き合わせる。超過は削減・変奏するか、意図的な密度として除外欄へ理由つきで記録して解消する（`02-narrative-craft §2-7` が正本）。検査モードでは watchlist を変更しない。

`cliche_check.py` は直訳クリシェ・感情ぼかし・圧縮癖のクラスタ（話単位上限・近接密集・場面末尾）を警告する。採否の場面テストと削除→直叙→接地の序列は `05-ai-guardrails §3-4`、圧縮癖5系統は `§3-5` が正本。警告の文脈判定（場面テスト・人物間共有・説明の二重化・複合発火）は次節の `ai-novel-detector` 診断が受け持ち、意図的な反復は `work/continuity/cliche-allowlist.txt` へ理由つきで登録して解消する。検査モードでは allowlist を変更しない。

`state_check.py` は対象ファイル単位ではなくリポジトリ全体の台帳を照合する。本文ファイルと状態差分ファイルの対応、作中日時、現在状態、日付の正本（`world-bible/core/08-timeline.md §3`）との突合、伏線台帳、事実IDのずれを拾う。本文の内容には踏み込まないため、出来事と状態差分の意味的な対応、canon-log との整合、人物ごとの位置・所持品・負傷は次節の目視照合で確認する。

- 検査モード：exit code、[NG]、[警告]、空行検査を記録し、変更しない。
- 修正モード：[NG]を意味・視点・文体を保つ最小差分で直し、exit 0まで再実行する。[警告]は統計指標として文脈判断し、正当な表現は残す。
- 空行の自動正規化はしない。Webペースト由来の肥大を修正する明示許可がある場合だけ、段落構造を確認して適用する。
- 意図的な他言語表記など判断が必要な違反は、勝手に意味を変えず要判断事項とする。

## 2. 視点・キャラ・情報格差・時系列を照合する

`guidelines/06-revision-checklist.md` のC〜Fを目視検査の正本とする。`work/pov-plan.md`、対象scene-card、登場人物のcharacter-sheet、`work/continuity/current-state.md`、canon-log、timelineの必要部分を読み、場面ごとに確認する。

- 視点運用（場面内一元固定、境界切替、3文アンカー、他人の内面・知り得ない情報の排除）と地の文の中立呼称が `02-narrative-craft §1` の規則どおりで、切替が pov-plan の割当と一致する
- 台詞、作中引用、明示的な内心の一人称、二人称、呼称、語尾、禁則語がcharacter-sheetと正典に一致する
- 作中日時、位置、負傷、所持品、関係が前話終了状態と連続し、本文中の新事実が既存正典と矛盾しない
- scene-cardの「今回返す約束」が具体的な選択・結果・関係変化として読め、作品固有の核を市場語彙で上書きしていない

pov-planがなければhead-hoppingと本文内部の知識整合だけ、character-sheetがなければ一人称・呼称・語尾の内部的な揺れだけを検査する。continuityやtimelineがなければ本文内部の時系列だけを検査し、未照合範囲を明記する。修正モードでも、資料不足を推測で正典化しない。

## 3. `ai-novel-detector` で診断する

1. `ai-novel-detector` で診断し、根拠、優先度、誤検出注意、引継ぎ票を作る。毎話の検証では通常診断（Quick Scan＋クラスタ走査の文脈判定）を既定とし、アーク境界・総合診断・重大な疑いがある場合だけ文体観点＋圧縮癖5系統のFull Detectへ広げる。正典・視点・時系列・情報格差の照合は本Skillの前段が受け持ち、診断Skillへ委ねない。
2. 検査モードでは所見と推奨修正を報告して終了する。
3. 修正モードでは高・中優先度の必要箇所だけを `humanize-ai-writing` へ渡す。
4. 改稿後に機械検出と視点・キャラ・情報格差・時系列照合を再実行する。
5. `ai-novel-detector` で変更箇所と波及箇所を再診断する。

低優先度の好みや作品意図まで機械的に均質化しない。意図的に残す所見は、残置理由を報告する。

## 4. 補助計測

```bash
bash scripts/chars.sh <対象ファイル>
```

字数は plot の目安と比較する。文章のリズムは `cliche_check.py` が出す「リズム参考値」（文長CV、同一文末の最長連続、長断定文の最長連続）を読む。

**これらは合否条件ではない。** 閾値を設けて数値を目標にすると、場面の速度と無関係な文長調整が始まり、かえって平坦になる。使い道は次の2つに限る。

1. 場面の機能（加速・減速・対話）に対して文長のばらつきが逆方向になっていないかを見る。
2. 同じ話数帯の他の話と比べ、リズムの幅が単調な方向へ動いていないかを見る。

読み取った所見は、`ai-novel-detector` の診断と合わせて改稿の優先度づけに使う。数値そのものを報告の結論にしない。

## 5. 報告する

- 実行モードと対象ファイル
- 文字数と資料の有無
- 機械検出のexit code、[NG]、[警告]、空行検査
- 視点・キャラ・情報格差・時系列検査の場面数と所見
- `state_check.py` の結果と、リズム計測から読み取った所見
- scene-cardの目標・状態差分・読者への約束との照合結果
- 文体診断の初回所見
- 修正モードの場合：実施した差分、humanize-ai-writingの改稿結果、全再検証、最終診断
- 未解決事項とユーザー判断が必要な項目

検査モードでは「合格／要修正」を報告し、「違反ゼロに修正済み」とは表現しない。修正モードでは全段階が完了した場合だけ「修正完了」と報告する。
